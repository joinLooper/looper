# Looper｜Player World UI Authority V1

**中央主控：** 🎛️ Looper App｜中央主控 02  
**日期：** 2026-10-18  
**性質：** 已核准的產品互動原則／實作樣式持續候選  
**首批工程：** W2-05（接續 W2-04 PR #59）

## 1. 唯一產品方向

玩家開啟 Forest 後，任務、知識、收藏、設定與進度都屬於同一個森林世界。

- 場景是玩家主要介面；森林物件本身是功能入口。
- 功能可以使用 Native 文字、清單、捲動與表單控制，但**呈現方式必須如遊戲物件的一部分**。
- 不以大片白底卡片、通用 App dashboard、標準 tab bar、制式齒輪與大量浮空圖示代替遊戲 UX。
- 道具外型沿用已核准的 B07「圓潤飽滿、手繪筆觸、偽 3D、有童趣但不 RPG」風格；禁止將實物材質直接變淡冒充遊戲美術。
- Forest / Treehouse 是既定兩個場景；任何浮層、書本或物件頁都不另開第三個遊戲世界。

## 2. 既有 Authority 不得變更

W2-02/B07 核准的任務木牌、闔上知識書、布包、更多吊牌、任務手札之 19 個 PNG 與兩處三列清單為來源基準。第一列綠勾、後兩列空框、每列兩條文字示意線。8 種勾選狀態依本機 UI state 切換。

任何後續 UI 重構不可更動像素來源、座標、錨點、Pivot 或角色 Canon；插畫後方的可閱讀紙張可以用程式樣式擴展，不得假冒重新核准的繪圖資產。

## 3. 已核准互動模型

- **任務／進度：** 點木牌開啟同一本森林手札；進度與完成狀態依原模型展示，不跳白卡。
- **知識：** 點樹樁小書，在森林內打開書頁回答；保留錯誤與正確的文字回饋。
- **背包：** 透過核准布包開啟收納頁；目前只顯示尚未開放的收藏提示，不虛構物品。
- **更多：** 透過核准吊牌開啟世界內設定及測試工具；這些測試控制並非正式玩家功能。
- **Welcome、舊 route：** 可以維持技術路由或直接連結，但玩家不能突然進入另一套工具風格。

## 4. 工程硬條件

- 畫面以 9:16 和 9:19.5 視角檢驗；重要入口、紙頁與閱讀文字不得裁切或互相蓋住。
- 觸控範圍至少 48dp；書頁支援可捲動動態文字及大字級。
- 尊重 Reduced Motion，並保留 Android 返回、iOS 收合操作與輔助讀取名稱。
- React Native 元件可繪製紙頁與按鈕，但不是獨立的核准角色／道具圖檔。
- 保留 `DemoState` 與本機測試固定資源；不得自行連動正式 Account、Economy、Reward、Backend、CO₂e 帳本。
- Android 真人驗收依使用者要求標記 **DEFERRED**；Web 自動化 PASS 與 Expo Go 正常啟動不等於 iPhone 最終視覺通過。

## 5. 驗收與發布界線

W2-04 功能流程已有使用者文字確認。W2-05 專注遊戲視覺連續性，需另交 9:16、9:19.5 Web 截圖及 iPhone Expo Go 真人畫面核准。

**視覺未獲中央確認時，工程維持 CANDIDATE、PR Draft / Unmerged。** 不因型別檢查、CI 或 Web 測試成功而提前宣稱 Final Art。

> 中央判準：「玩家從森林打開功能，始終像在操作森林裡的生活物件，而不是離開遊戲打開網站或便民工具。」
