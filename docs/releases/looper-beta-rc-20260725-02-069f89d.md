classification was actual LINE/LIFF credential QA. That gate has now passed with
two real LINE accounts:

## Security gates

- Caller-controlled `userId` has no authorization effect.
- Legacy economic write routes return HTTP 410 without ledger side effects.
- Task-code expiry is advanced by the canonical server path.
- Lost task-code response recovery is idempotent and fingerprint conflicts return
  HTTP 409.
- Merchant current-code and pending-submission polling is active.
- Merchant stale-session cleanup removes protected data after 401/403.
- Knowledge-card rewards persist canonical server-owned +30 EXP.
- Resource mutations use the append-only ledger.
- Session tokens are stored as hashes.
- CORS allows the exact Player, Merchant, and Admin production origins.
- Session cookies use HttpOnly, Secure, and SameSite=Lax.

## Known limitations

- The LINE Login Channel remains in **Developing** status. Closed-beta
  participants must first receive a Tester or Admin role.
- The production data service currently uses one Railway instance and a persistent
  SQLite volume.
- PostgreSQL migration remains future Production Data Infrastructure work.
- T6/D9 dynamic masks remain pending.
- Full iOS/Android device-specific UI ratio calibration remains a separate QA
  effort.
- Site-wide copy, dialog, and layout-ratio calibration is not complete.

These limitations do not block the **Beta Candidate** classification, but this
build is not **Production Ready**.
